1. 简介							*simpleclipboard*

SimpleClipboard 是一个 Vim9 插件。即使 Vim 没有 |+clipboard|，它也能把
yank、可视选区或指定行复制到系统剪贴板。

首选路径由一个 Vim 可加载的 Rust 客户端动态库和本机剪贴板守护进程组成。
二者通过 TCP 交换有边界、有确认的 SCB1 消息。守护进程使用 arboard 写入
桌面剪贴板。首选路径不可用时，插件会选择适合当前环境的外部命令或 OSC52。

0.2 版统一以实际交付的 loopback TCP 为准，并删除 0.1 文档中过时的
Unix socket 与 systemd socket activation 说明。

主要能力：

- TextYankPost 后自动复制成功的 yank；
- 默认使用 <leader>y，不覆盖 Vim 原生 y；
- 精确保留字符、行和块可视选区；
- 支持 Linux/X11、原生 Wayland、macOS、WSL、SSH 与常见容器环境；
- 支持自定义 argv 形式的复制命令；
- 可查询状态并在环境变化后刷新探测缓存；
- 守护进程消息上限 10 MiB，OSC52 有独立的安全上限。

2. 要求与兼容性				*simpleclipboard-requirements*

完整功能要求：

- Vim 9.0 或更高版本；
- |+job|、|+channel|；
- Rust 客户端路径需要 |+libcall|；
- Rust daemon 路径需要 Vim 的 &encoding 为 utf-8；
- 构建后端需要满足 Cargo.toml 中 rust-version 的 Rust 工具链。

Debian/Ubuntu 构建依赖可安装为： >

  sudo apt-get install pkg-config libwayland-dev libxkbcommon-dev
<

没有 +libcall 时，Rust 客户端不可用，但外部命令和 OSC52 回退仍可使用。
没有 +timers 时不执行防抖，TextYankPost 自动复制会立即运行。

可选外部命令：

- macOS：pbcopy；
- Wayland：wl-copy；
- X11：xsel 或 xclip；
- WSL：clip.exe；
- OSC52：base64，以及允许 OSC52 剪贴板写入的终端。

本插件不支持 Neovim。Windows 原生 Vim 目前不是受支持目标；WSL 通过
clip.exe 或 OSC52 支持复制到 Windows 剪贴板。

Wayland 守护进程通过 arboard 的 wayland-data-control 功能访问原生
Wayland 数据控制协议。若 compositor 不支持该协议，可回退到 wl-copy 或
XWayland 工具。

3. 安装						*simpleclipboard-install*

vim-plug 示例： >

  Plug 'beamiter/simpleclipboard', { 'do': './install.sh' }
<

Vim packages 示例： >

  git clone https://github.com/beamiter/simpleclipboard.git \
    ~/.vim/pack/plugins/start/simpleclipboard
  cd ~/.vim/pack/plugins/start/simpleclipboard
  ./install.sh
<

install.sh 会把 release 构建产物安装到插件的 lib/ 目录：

Linux：

  lib/libsimpleclipboard.so
  lib/simpleclipboard-daemon
  lib/simpleclipboard-client

macOS：

  lib/libsimpleclipboard.dylib
  lib/simpleclipboard-daemon
  lib/simpleclipboard-client

simpleclipboard-client 每次运行发一个请求（ping、从标准输入读的 set、
写到标准输出的 get），密钥从 $SIMPLECLIPBOARD_TOKEN 读取。它是唯一能
拿到 get 结果的途径，因为 libcallnr() 只能返回数字。
注意：插件目前还没有驱动它——Vim 侧的每一次复制仍然走同步的库调用，
也没有任何命令会读剪贴板。想要 get，请自己在 shell 里运行它。

插件目录必须位于 'runtimepath'，否则自动发现无法找到 lib/ 下的文件。
也可以使用 |g:simpleclipboard_libpath| 和
|g:simpleclipboard_daemon_path| 指定绝对路径。

安装器始终为当前 rustc 的 host target 构建，避免 Cargo build.target 设置或
旧的交叉编译产物被误装进当前 Vim。

生成帮助标签： >

  :helptags /absolute/path/to/simpleclipboard/doc
<

SSH 自动隧道配置是可选操作，必须显式请求： >

  ./install.sh --with-ssh-tunnel --ssh-host my-workstation
<

将 my-workstation 替换为 ~/.ssh/config 中一个明确的 Host 别名。安装器拒绝
通配符，避免隧道意外作用于其他 SSH 目标。托管的 Match 块在建立 SSH 连接时
求值，且只有 pgrep 检测到本机 simpleclipboard-daemon 才启用；daemon 后启动
时需要重连。安装器只维护一个 host 块，改用不同 --ssh-host 会替换它；多个
别名应手工配置 Host 块。

自定义端口示例： >

  ./install.sh --with-ssh-tunnel --ssh-host my-workstation \
    --daemon-port 12343 --tunnel-port 12345
<

这两个端口参数只修改托管 SSH 块；需要自行同步 daemon 的
SIMPLECLIPBOARD_ADDR、|g:simpleclipboard_port| 与
|g:simpleclipboard_tunnel_port|。若显式 |g:simpleclipboard_address| 仍包含旧
tunnel 端口，也必须同步修改。

4. 快速开始					*simpleclipboard-quick-start*

本地桌面环境通常不需要配置：

- 正常使用 y；默认开启的 TextYankPost 自动复制成功的 yank；
- 普通模式按 <leader>y，复制无名寄存器；
- 可视模式选中文本后按 <leader>y，复制精确选区；
- 执行 :SimpleCopyRegister a 可复制寄存器 a，:SimpleCopyClear 可显式清空；
- 执行 :SimpleCopyPath / :SimpleCopyLocation 可复制当前文件或精确光标位置；
- 执行 :SimpleCopyStatus 查看环境、地址和当前后端；
- 隧道、显示服务器或容器网络变化后执行 :SimpleCopyRefresh。

关闭自动复制但保留命令和映射： >

  let g:simpleclipboard_auto_copy = 0
<
该选项在每次 yank 时重新读取，运行期改动立即生效。临时关闭还可以用： >

  :SimpleCopyToggle
  :SimpleCopyPause 60
<

关闭默认映射并自定义： >

  let g:simpleclipboard_no_default_mappings = 1
  nmap <leader>Y <Plug>(SimpleCopyYank)
  xmap <leader>Y <Plug>(SimpleCopyVisual)
<

5. 命令						*simpleclipboard-commands*

							*:SimpleCopyYank*
:SimpleCopyYank
	复制无名寄存器的内容。

						*:SimpleCopyRegister*
:SimpleCopyRegister [name]
	复制任意 Vim 寄存器。[name] 可为一个寄存器字符；unnamed、clipboard、
	primary 分别是 "、+、* 的易读别名。省略时复制无名寄存器。

							*:SimpleCopyVisual*
:SimpleCopyVisual
	复制最近一次可视选区，并保留字符、行或块选择的边界。

						*:SimpleCopyRange*
:[range]SimpleCopyRange
	复制 {range} 中的完整行。没有显式范围时，范围为整个缓冲区。

						*:SimpleCopyClear*
:SimpleCopyClear
	显式清空系统剪贴板。空文本仍走与普通复制相同的 daemon ACK、外部命令
	与 OSC52 回退链，不会被误判成“空寄存器”。

						*:SimpleCopyPath*
:SimpleCopyPath[!]
	复制当前文件路径；默认相对当前窗口/标签页/全局生效的 cwd，! 改为绝对
	路径。空格与 UTF-8 原样复制，不做 shell 转义；无名或非文件 buffer 会明确
	拒绝。

						*:SimpleCopyLocation*
:SimpleCopyLocation[!]
	复制 path:line:column。行、列均从 1 开始，列按字符而不是 Vim byte column
	计数；! 使用绝对路径。与其他显式命令一样走完整确认与回退链。

						*:SimpleCopyFormat*
:SimpleCopyFormat[!] {template}
	用 {path}、{dir}、{file}、{line}、{column} 生成并复制自定义文件引用；
	! 令 path/dir 使用绝对路径。{{ 与 }} 表示字面大括号。空模板、未知
	占位符、嵌套或不配对大括号会在进入剪贴板流水线之前拒绝，因此不会复制
	半成品；路径自身包含的占位符样文本不会被二次展开。

						*:SimpleCopyToggle*
:SimpleCopyToggle
	开关 |g:simpleclipboard_auto_copy| 并报告新状态。该选项在每次 yank
	时重新读取，因此立即生效；关闭时还会丢弃仍在防抖等待中的旧 yank。
	显式命令与映射不受影响。

						*:SimpleCopyPause*
:SimpleCopyPause {seconds}
	暂停自动复制 {seconds} 秒（1..86400），到期后恢复暂停前的取值。
	适合在处理凭据、令牌等敏感文本前临时关闭。重复执行会重新计时并
	保留第一次暂停之前的取值；|:SimpleCopyToggle| 会取消进行中的暂停。
	需要 |+timers|：没有定时器时命令拒绝执行，而不是永久关闭自动复制。

						*:SimpleCopyStart*
:SimpleCopyStart
	按当前配置启动本地守护进程。SSH 或容器场景不会误启动不合适的
	远端进程；地址已被占用时复用而不是再启动一个。

						*:SimpleCopyStop*
:SimpleCopyStop
	仅停止由当前 Vim 实例启动并持有的守护进程 job。不会根据 PID
	文件或端口杀死其他 Vim、systemd 或用户启动的守护进程。

						*:SimpleCopyStatus*
:SimpleCopyStatus
	输出当前环境、路由地址、守护进程状态和可用后端。无论
	g:simpleclipboard_debug 是否开启，本命令都会显示结果。
	它本身不会因为选项写错而失败——最需要它的时候正是配置坏了的
	时候。token 只报告状态，不回显取值：`token=off`、
	`token=configured` 或 `token=invalid (must be a string)`。

						*:SimpleCopyRefresh*
:SimpleCopyRefresh
	清除环境探测、动态库、命令和后端缓存，然后重新探测。修改地址、
	启动 SSH 隧道、安装复制命令或切换显示服务器后使用。

7. 选项						*simpleclipboard-options*

所有选项应在插件加载前设置，一般放在 vimrc 中。
例外是 |g:simpleclipboard_auto_copy|：它在每次 yank 时重新读取，运行期修改
立即生效。改动其他选项后执行 |:SimpleCopyRefresh|。

						*simpleclipboard-option-validation*
类型写错不会让复制崩掉。插件加载时、|:SimpleCopyRefresh| 与 |:SimpleCopyStatus|
都会逐条报告有问题的选项，说明期望类型、实际看到的值以及随之采取的行为，
例如： >

  g:simpleclipboard_port must be a positive number, but is a string ("12343"); using the default 12343
  g:simpleclipboard_debounce_ms must be a number, but is a string ("soon"); using the default 50
<
数字字符串按十进制解释（引号包住端口是常见写法），布尔值按它强制转换出的
0/1 解释，其余无法解释的取值退回文档中的默认值。报告里写的永远是真正生效的
取值，不会在实际用 1 的时候声称"用默认值 12343"。例外是
|g:simpleclipboard_auto_copy_registers|、
|g:simpleclipboard_auto_copy_max_bytes| 与 |g:simpleclipboard_osc52_limit|：
它们控制哪些内容可以离开 Vim，取值不可用时失败关闭而不是猜一个更宽松的
默认值——前两个在完全读不出数字时跳过自动复制，OSC52 上限取 0、负数或读不出
数字时直接封掉 OSC52 而不是退回 75000。加不加引号都一样：'0' 与 '-5' 和
0、-5 一样封掉 OSC52，报告里写的也是"封掉"，不会去提那个并没有生效的 75000。
写成字符串的字节上限仍然是字节上限，会照常生效。
|g:simpleclipboard_token| 只报告类型和长度，不回显取值。列表选项的元素也会
校验：|g:simpleclipboard_copy_command| 必须是非空字符串列表，
|g:simpleclipboard_auto_copy_registers| 必须是字符串列表。

守护进程与自动复制 ~

					*g:simpleclipboard_daemon_enabled*
g:simpleclipboard_daemon_enabled
	默认：1
	是否启用 Rust 守护进程后端。置 0 后直接使用回退后端。

					*g:simpleclipboard_daemon_autostart*
g:simpleclipboard_daemon_autostart
	默认：1
	在合适的本地环境中于 VimEnter 自动启动守护进程。

					*g:simpleclipboard_daemon_autostop*
g:simpleclipboard_daemon_autostop
	默认：0
	退出 Vim 时，是否停止当前 Vim 自己启动的守护进程 job。即使开启，
	也不会停止仅被探测到的外部守护进程。

					*g:simpleclipboard_auto_copy*
g:simpleclipboard_auto_copy
	默认：1
	是否在 TextYankPost 后自动复制成功的 yank。与其他选项不同，它在每次
	yank 时重新读取，运行期修改立即生效：在 yank 凭据之前执行
	`:let g:simpleclipboard_auto_copy = 0`（或 |:SimpleCopyPause|）确实能挡住
	这一次 yank。关闭时仍在防抖等待中的旧 yank 也会被丢弃。
	另见 |:SimpleCopyToggle|。

				*g:simpleclipboard_auto_copy_registers*
g:simpleclipboard_auto_copy_registers
	默认：[]
	自动复制的源寄存器白名单。空列表保持旧行为：除黑洞寄存器 _ 外全部
	yank 都可复制。非空时只接受列出的寄存器；普通无名 yank 写作
	'unnamed' 或 '"'。例如 ['unnamed', 'a']。被过滤的新 yank 会取消仍在
	防抖等待中的旧 yank，避免旧敏感内容稍后意外写入剪贴板。

				*g:simpleclipboard_auto_copy_max_bytes*
g:simpleclipboard_auto_copy_max_bytes
	默认：0
	TextYankPost 自动复制允许的最大 UTF-8 字节数；0 表示不限制。只约束
	自动复制，:SimpleCopyRegister、:SimpleCopyRange 等显式操作不截断也不拒绝。
	写成数字字符串（'4096'）按十进制解释；完全读不出数字时自动复制整体
	跳过，|:SimpleCopyStatus| 会显示 max=invalid (expected number)。

					*g:simpleclipboard_debounce_ms*
g:simpleclipboard_debounce_ms
	默认：50
	自动复制的防抖时间，单位毫秒。

					*g:simpleclipboard_no_default_mappings*
g:simpleclipboard_no_default_mappings
	默认：0
	置 1 后不创建 <leader>y 默认映射。

路径和路由 ~

					*g:simpleclipboard_libpath*
g:simpleclipboard_libpath
	默认：''
	Rust 客户端动态库的绝对路径。为空时搜索 runtimepath/lib。

					*g:simpleclipboard_daemon_path*
g:simpleclipboard_daemon_path
	默认：''
	守护进程的绝对路径。为空时搜索 runtimepath/lib。

					*g:simpleclipboard_bind_addr*
g:simpleclipboard_bind_addr
	默认：'127.0.0.1'
	由 Vim 启动的守护进程所使用的监听地址。非 loopback 地址必须同时
	设置非空 token，否则守护进程拒绝启动。

					*g:simpleclipboard_port*
g:simpleclipboard_port
	默认：12343
	本地主守护进程的 TCP 端口。

					*g:simpleclipboard_tunnel_port*
g:simpleclipboard_tunnel_port
	默认：12345
	SSH RemoteForward 在远端 loopback 上使用的端口。

					*g:simpleclipboard_address*
g:simpleclipboard_address
	默认：''
	显式 host:port 地址。非空时完全覆盖环境、port 和 tunnel_port
	自动探测，并优先尝试该 daemon。显式地址必须同时配置非空 token。

					*g:simpleclipboard_token*
g:simpleclipboard_token
	默认：''
	预共享密钥。两端设置相同的非空长随机值后，请求与 ACK 使用
	AES-256-GCM 认证加密，token 本身不会上网。remote、container、显式
	custom address 以及非 loopback daemon 强制要求设置。必须是最多 4096
	字节的 UTF-8 字符串，且不能包含 U+0001。

				*g:simpleclipboard_container_host*
g:simpleclipboard_container_host
	默认：''
	可选的容器宿主机名称或 IP。为空时读取默认路由，并尝试
	host.docker.internal。

回退 ~

					*g:simpleclipboard_copy_command*
g:simpleclipboard_copy_command
	默认：[]
	自定义复制命令，类型必须为 list<string> argv，例如：
>
	  let g:simpleclipboard_copy_command = ['wl-copy', '--type', 'text/plain']
<
	插件直接启动 argv，不经过 shell。进程必须保持附着，直到剪贴板写入完成。

					*g:simpleclipboard_disable_osc52*
g:simpleclipboard_disable_osc52
	默认：0
	置 1 后完全禁用 OSC52 回退。

					*g:simpleclipboard_osc52_limit*
g:simpleclipboard_osc52_limit
	默认：75000
	OSC52 路径接受的最大 UTF-8 payload 字节数。它独立于 daemon 的
	10 MiB 上限。
	必须是正数。取 0、负数或读不出数字时失败关闭：直接封掉 OSC52
	（|:SimpleCopyStatus| 显示 `OSC52: blocked (invalid limit)`），
	而不是悄悄退回 75000。转义序列一旦写进终端就收不回来，还可能
	经 tmux/screen 落进外层会话的日志，所以这里不猜默认值。

					*g:simpleclipboard_osc52_truncate*
g:simpleclipboard_osc52_truncate
	默认：0
	默认在超限时拒绝 OSC52，避免悄悄复制不完整内容。OSC52 已是 daemon
	和命令候选之后的最终回退，因此拒绝会让本次复制明确失败。置 1 才允许
	截断到 osc52_limit。截断按字符边界进行，不会切开一个码点。

					*g:simpleclipboard_osc52_terminator*
g:simpleclipboard_osc52_terminator
	默认：'bel'
	OSC 52 序列的结束符：'bel' 是 BEL（0x07），'st' 是标准字符串结束符
	ESC \。绝大多数终端接受 BEL；少数只认 ST。取值大小写不敏感，
	写错时报告一次并退回 'bel'。

					*g:simpleclipboard_osc52_selection*
g:simpleclipboard_osc52_selection
	默认：'c'
	OSC 52 写哪个选区：'c' 是 CLIPBOARD，'p' 是 X11/Wayland 的 PRIMARY

	仍然只写 CLIPBOARD。取值大小写不敏感，写错时报告一次并退回 'c'。

					*g:simpleclipboard_osc52_tty*
g:simpleclipboard_osc52_tty
	默认：''

	多路复用器会自动处理：$TMUX 非空时套 tmux 透传序列；screen 下
	（$STY 非空，或 'term'/$TERM 以 screen 开头）套 DCS 封装，并把超过

8. 工作原理					*simpleclipboard-architecture*

本地首选路径：

  Vim
    -> libcallnr() Rust 客户端
    -> 127.0.0.1:12343
    -> simpleclipboard-daemon
    -> arboard
    -> 桌面剪贴板

Vim 使用版本化 ABI：

  SCB2\x01address\x01action\x01token\x01text

text 位于最后，因此可以保留其中的 U+0001。FFI 返回 0 表示失败、1 表示确认
成功、2 表示剪贴板写入可能已经开始但结果无法确认；旧导出入口继续保留用于
兼容。

TCP 消息使用 SCB1 帧：

1. daemon 先返回带 32 字节随机 challenge 的短帧；
2. 每帧以 4 字节 ASCII 魔术字 SCB1 开头；
3. 随后是 4 字节大端 payload 长度；
4. client 发送最大 10 MiB、严格解码的手写二进制请求；
5. daemon 返回单独带帧边界的 ACK；hello 与 ACK payload 上限为 4 KiB。

token 非空时，协议用 SHA-256 域分离派生 request/ACK 两把密钥，并用
AES-256-GCM 保护双向 payload。请求绑定 server challenge，ACK 同时绑定
challenge 与 request nonce，因此 token 和剪贴板明文都不会出现在网络上，
捕获的请求也不能转投到另一连接。token 为空时，仅本机 loopback 的零配置
模式仍使用明文 payload。

daemon 持有 arboard Clipboard 上下文。在 X11 和部分 Wayland 剪贴板
模型中，复制源需要继续服务内容，因此保持 daemon 存活很重要。

daemon 命令行：
>
  simpleclipboard-daemon --help
  simpleclipboard-daemon --version
<

daemon 环境变量：

SIMPLECLIPBOARD_ADDR
	监听地址，默认 127.0.0.1:12343。

SIMPLECLIPBOARD_TOKEN
	loopback 上可选、非 loopback 强制要求的 UTF-8 预共享加密密钥；最大
	4096 字节。Vim ABI 使用的值不能包含 U+0001。

SIMPLECLIPBOARD_PID_FILE
	PID 文件路径；设为 - 可禁用 PID 文件。默认使用
	$XDG_RUNTIME_DIR/simpleclipboard.pid；若该变量未设置或为空，则使用系统
	临时目录中的每用户文件。文件锁保证每个 PID 文件路径最多一个 daemon。

RUST_LOG
	error、warn、info、debug、trace，或 simpleclipboard=<level>。

daemon 不可用时，插件按环境选择外部命令。内置候选顺序为 pbcopy、
wl-copy、WSL 的 clip.exe、xsel、xclip。用户配置的
|g:simpleclipboard_copy_command| 最先尝试；若异步命令以失败状态退出，会继续
尝试后续平台候选，最后才使用 OSC52。外部 job 串行执行；等待期间的多次请求
只保留最新文本，防止较慢的旧命令反向覆盖新复制。

OSC52 默认最多接受 75000 个 UTF-8 字节。超限默认失败而不截断；只有显式开启
|g:simpleclipboard_osc52_truncate| 才会产生部分内容。

9. SSH、容器与 WSL				*simpleclipboard-remote*

普通 SSH 场景可以用 RemoteForward 将远端 loopback 端口转发到本地桌面
daemon。以下是无条件的手工配置；安装器生成的是安装章节所述带进程检测的
Match 块：
>
  Host development-host
      RemoteForward 12345 127.0.0.1:12343
      ExitOnForwardFailure yes
<

远端 Vim 随后连接 127.0.0.1:12345。remote、container 和显式 custom
daemon 路由没有 token 时会在探测前直接阻断：
>
  let g:simpleclipboard_address = '127.0.0.1:12345'
  let g:simpleclipboard_token = 'replace-with-the-same-long-random-value'
  let g:simpleclipboard_daemon_autostart = 0
<

本地手动启动示例：
>
  SIMPLECLIPBOARD_ADDR=127.0.0.1:12343 \
  SIMPLECLIPBOARD_TOKEN='replace-with-the-same-long-random-value' \
  ./lib/simpleclipboard-daemon
<

OpenSSH 的远端转发默认仅监听远端主机 loopback。普通 bridge 容器通常
不能通过宿主机 IP 访问这个 loopback 端口。优先使用 OSC52、host
network，或经过明确设计且带认证的代理，不要为了容器便利而暴露无认证
端口。

特殊容器网络建议直接设置 |g:simpleclipboard_address|。地址非空时不再
使用自动探测。网络变化后执行 |:SimpleCopyRefresh|。

WSL 默认可探测 clip.exe。也可显式设置：
>
  let g:simpleclipboard_copy_command = ['clip.exe']
<

10. 安全						*simpleclipboard-security*

- Vim 管理的 daemon 默认只监听 127.0.0.1；
- daemon 在无 token 时拒绝非 loopback 监听；Vim 也拒绝无 token 的
  remote、container 和 custom daemon 路由；
- token 是预共享密钥且不会直接上网；非空时使用 AES-256-GCM
  认证加密请求与 ACK，并用每连接 challenge 防止跨连接重放；
- token 为空时 loopback payload 仍是明文；共享机器应使用长随机 token；
- AES-GCM 不隐藏地址、密文长度、时间和可用性；跨机器仍建议使用 SSH、
  VPN 或其他可信传输作为纵深防御；
- 不要把 token 写入公开 vimrc、shell 历史或问题报告；
- 剪贴板内容可能包含密码、密钥和个人信息；
- OSC52 是否生效由终端或 multiplexer 安全策略决定；
- :SimpleCopyStop 只停止当前 Vim 启动的 job，不根据 PID 或端口杀进程。

SHA-256 密钥派生不是密码拉伸；不要使用短口令或可猜值，否则记录密文的
攻击者可以离线猜测。token 应由足够长的随机值组成，并存放在权限受限的
配置或环境文件中。

漏洞请通过 GitHub Security Advisory 私下报告：

https://github.com/beamiter/simpleclipboard/security/advisories/new

详见仓库 SECURITY.md。

11. systemd 用户服务				*simpleclipboard-systemd*

0.2 版只能作为普通 service 运行。不要创建 .socket unit；daemon 不接收
继承的监听 fd。
>
  [Unit]
  Description=SimpleClipboard daemon
  After=graphical-session.target

  [Service]
  Type=simple
  Environment=SIMPLECLIPBOARD_ADDR=127.0.0.1:12343
  Environment=SIMPLECLIPBOARD_PID_FILE=-
  ExecStart=%h/.vim/pack/plugins/start/simpleclipboard/lib/simpleclipboard-daemon
  Restart=on-failure

  [Install]
  WantedBy=default.target
<

保存为 ~/.config/systemd/user/simpleclipboard.service，修正 ExecStart 后：
>
  systemctl --user daemon-reload
  systemctl --user enable --now simpleclipboard.service
<

由 systemd 管理 daemon 时：
>
  let g:simpleclipboard_daemon_autostart = 0
  let g:simpleclipboard_daemon_autostop = 0
<

token 应通过权限受限的 systemd 环境文件提供，不要写入其他用户可读的
unit 文件。

12. 状态、刷新与日志				*simpleclipboard-diagnostics*

						*simpleclipboard-status*
|:SimpleCopyStatus| 始终输出诊断，不依赖 debug 开关。建议先运行它确认：

- 当前是否为 SSH、容器或 WSL；
- 最终 daemon 地址；
- daemon 是否启用、是否可达；
- 当前检测到的命令和 OSC52 条件；
- configuration: 一行汇总选项校验结果，ok 或 N problem(s) 加逐条说明。

daemon 的 reachable 来自真实协议 ping；命令与 OSC52 仅表示检测到候选或
基本条件，不保证实际剪贴板写入一定成功。

						*simpleclipboard-refresh*
|:SimpleCopyRefresh| 会清除环境和后端缓存再重新探测。以下情况后应执行：

- 建立或断开 SSH tunnel；
- 修改 address、port、token 或路径；
- 新安装 wl-copy、xsel、xclip 等命令；
- 显示服务器或容器网络发生变化。

若当前 Vim 拥有一个正在运行的 daemon，Refresh 会先安全停止它，再用新的
本地配置重启；即使 |g:simpleclipboard_daemon_autostart| 为 0 也如此。

						*simpleclipboard-logging*
详细日志：
>
  let g:simpleclipboard_debug = 1
<

写入文件：
>
  let g:simpleclipboard_debug = 1
  let g:simpleclipboard_debug_to_file = 1
<

分享日志前检查其中是否含地址、用户名或其他敏感环境信息。

13. 疑难解答					*simpleclipboard-troubleshooting*

客户端动态库或 daemon 找不到 ~

重新运行 ./install.sh；检查 :set runtimepath?；或设置
|g:simpleclipboard_libpath| 和 |g:simpleclipboard_daemon_path| 的绝对路径。

Address already in use ~

选定端口已被其他 daemon 或进程占用。使用匹配 token 复用它，通过它的
所有者停止它，或选择另一端口。若已有 SimpleClipboard daemon 持有默认 PID
文件锁，第二个实例还必须设置不同的 SIMPLECLIPBOARD_PID_FILE；设为 - 会放弃
该单实例保护。不要使用 :SimpleCopyStop 停止非本 Vim 拥有的 daemon；该命令
会安全地拒绝。

Token rejected ~

确认 daemon 的 SIMPLECLIPBOARD_TOKEN 和 Vim 的
|g:simpleclipboard_token| 完全相同。

Outcome uncertain ~

daemon 可能已经开始写剪贴板，但 client 未能确认最终结果。状态中的 outcome
会显示 uncertain。插件会禁止立刻启动外部命令或 OSC52，避免迟到的 daemon
写入覆盖刚刚执行的回退。

纯 Wayland 失败 ~

确认 compositor 支持 data-control；安装 wl-copy 作为回退，然后执行
|:SimpleCopyRefresh|。有 XWayland 时也可使用 xsel/xclip。

WSL 失败 ~

确认 executable('clip.exe') 返回 1；否则检查 PATH，或设置
|g:simpleclipboard_copy_command| 为 ['clip.exe']。

OSC52 无效 ~

终端可能禁止剪贴板写入。tmux 用户还需要按当前 tmux 版本配置 passthrough。
若明确不希望使用 OSC52，设置 |g:simpleclipboard_disable_osc52|。

大文本失败 ~

daemon 协议消息上限为 10 MiB。OSC52 默认上限是 75000 个 UTF-8 字节，且默认
不截断。若一定接受部分内容，显式开启
|g:simpleclipboard_osc52_truncate|。

自动复制有延迟 ~

调整 |g:simpleclipboard_debounce_ms|，或关闭
|g:simpleclipboard_auto_copy| 并使用显式映射。

14. 从 0.1 升级					*simpleclipboard-upgrade*

0.2 加固了协议处理并更改进程生命周期。0.1 文档描述了 Unix socket，
但当时实际交付的后端已经使用 TCP：

1. 停止 0.1 daemon，禁用并删除按旧文档创建的 simpleclipboard.socket unit；
2. 更新仓库后重新运行 ./install.sh，确保动态库与 daemon 来自同一版本；
3. 删除过时的 Unix socket 设置；TCP endpoint 默认为 127.0.0.1:12343；
4. 检查安全设置：remote、custom 和非 loopback 路由必须有匹配 token；
   0.2 会用它启用认证加密；
5. 检查 OSC52：超限现在默认安全失败，只有显式选择才截断；
6. 执行 :SimpleCopyRefresh 和 :SimpleCopyStatus。

0.1 与 0.2 的 client/daemon 不应混用。0.2 没有 socket activation
兼容层。

DAEMON LIFECYCLE                                      *simpleclipboard-daemon*

The plugin starts and owns the daemon itself with |job_start()|.  The daemon's
stdout and stderr go to null, and requests do not travel over them at all:
they are framed binary messages on a TCP connection, sent synchronously by the
Rust client library through |libcall()|.  See |simpleclipboard-architecture|.

What that gives you:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- Only the job this Vim instance started is ever stopped.  No daemon is killed
  by PID file or by port, so another Vim, a systemd unit or a hand-started
  daemon is left alone.
- |:SimpleCopyStop| waits for the daemon to drain an in-flight clipboard write
  before giving up on it.
- A daemon is never started onto an address something else already owns: it
  could only fail to bind, and with its stderr discarded that failure would
  show up as nothing but a slow yank.  The second and later Vim instances use
  the daemon that is already running.
- One copy triggers at most one daemon start attempt.  When that does not
  produce a reachable daemon, the copy continues down the external-command and
  OSC52 fallback chain instead of forking again.

What it deliberately does not do:

- No automatic restart, no exponential backoff, no crash-loop breaker.  After a
  daemon dies, copies use the fallback chain; run |:SimpleCopyRestart| to get
  the preferred path back.
- No request/reply correlation or per-request timeout in Vim: the client call
  is synchronous, and the connect and I/O deadlines live in the Rust client.
- No daemon stderr transcript.  Daemon output is discarded, so |:SimpleCopyLog|
  shows this plugin's own view of the daemon rather than the daemon's own log.

                                                      *:SimpleCopyHealth*
:SimpleCopyHealth
        An alias for |:SimpleCopyStatus|, following the suite-wide
        :<Plugin>Health convention.  It prints exactly the same report:
        environment, route address, daemon reachability, detected backends,
        option validation and the last copy's outcome.

                                                      *:SimpleCopyRestart*
:SimpleCopyRestart
        Stop the daemon owned by this Vim instance, then start a fresh one with
        the current configuration.

                                                      *:SimpleCopyLog*
:SimpleCopyLog
        Open this plugin's transcript in a scratch buffer: the most recent few
        hundred entries.  Three kinds of entry go in, all of them unconditional
        and none of them dependent on |g:simpleclipboard_debug| having been on
        beforehand — which it never is before the copy that goes wrong:

        - every notification this plugin printed, daemon lifecycle included;
        - every backend failure behind a fallback, and every route decision
          (blocked daemon route, refused plaintext, skipped automatic copy);
        - the route each copy finally took, as "Copy route: <method> (N
          bytes)".

        With |g:simpleclipboard_debug| on, the same lines are echoed as they
        happen, together with the finer-grained probe detail that is not kept
        in the ring.

DAEMON COMMAND LINE                               *simpleclipboard-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it with
|job_start()| and then speaks the framed binary TCP protocol to it, configured
entirely through the SIMPLECLIPBOARD_ADDR and SIMPLECLIPBOARD_TOKEN environment
variables.  For diagnosis it also answers: >

  simpleclipboard-daemon --version
  simpleclipboard-daemon --help
  simpleclipboard-daemon --self-test
<
--self-test runs one authenticated request through key derivation, AEAD
sealing, framing and the response binding in-process, and prints "ok".  It
never touches the desktop clipboard, so it works over SSH and in containers.
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/; the previous
lib/ is left untouched when it fails.

Every daemon in the simple* suite answers these three the same way.

VENDORED SUPERVISOR                               *simpleclipboard-simplecore*

autoload/simpleclipboard/core.vim is the suite's shared daemon supervisor and
the test harness beside it is its regression suite.  Both are vendored from the
.simplecore bundle rather than written here — each plugin carries its own copy
so that installing this plugin alone is enough.  This plugin's own daemon path
does not route through the supervisor yet: it manages the job directly, as
|simpleclipboard-daemon| describes.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.

The bundle lives at https://github.com/beamiter/simplecore.  To change the
supervisor, clone it beside the plugins, edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<
